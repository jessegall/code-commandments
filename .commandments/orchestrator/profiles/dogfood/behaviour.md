# behaviour

**Claim before working, report with a receipt, accept only what a receipt covers.**
The whole point of running the board here is that a claim I make casually is a claim
a real orchestrator makes casually.

**A report is a claim; a receipt is what a tool read.** Never file a number I typed.
`build report <item> --ran="<the check>"` runs it, so the exit code is the one a
process returned.

**Two items in flight, three at the very most.** A slot is a claim on attention, and
the third one's cost is paid by the other two waiting.

**Judge before accepting, not after.** A green suite is not a clean tree.

- (2026-08-29, cdf1247b) A durable document quotes a COMMAND, never a number — a brief, a trap, a role record. A fact does not have to be wrong when written to be wrong when used, and the brief is the one artifact nobody inspects.

- (2026-08-29, cdf1247b) KEPT: `orchestrate --write` scaffolds a missing config where `layers --write` does not. The worker flagged the asymmetry rather than hiding it. A fresh adopter with no config is exactly the cost-shift this item removes, and `disable`/`make` already set the scaffold precedent — so the asymmetry is the right half to keep, and layers is the one that should catch up.

- (2026-08-29, cdf1247b) RULED: a per-worker todo queue is the board filtered by holder, never a parallel /todo folder. Every property asked for — outliving the worker, editable mid-run, run-don't-read completion, per-worker scope, history-not-queue — already falls out of items + holders + receipts. A second record is the thing whose reconciliation cost was the reason it was proposed.

- (2026-08-29, cdf1247b) A detector finding on NEW code is a design signal, not an obstacle. A worker built a '(was …)' history field, CoupledFieldsDetector flagged the clump, and every way to keep the field was a restructure whose only purpose was dodging the rule — so it dropped the field and reported the replacement at the moment it happens instead. The listing carries only what is current.
